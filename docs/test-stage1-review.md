# 프로젝트 테스트 1단계 검토

상태: 판단 보류 후보 2건 해결, 확정 A 대상 단위 테스트 완료

## 범위와 현재 상태

- `AGENTS.md`의 동작별 A/B/C/D 기준을 적용했다. 테스트 작성과 소스 리팩토링은 수행하지 않았다.
- 프로젝트 파일 목록과 기존 테스트 13개를 확인한 뒤, 확정한 A 대상의 신규·보강 테스트를 포함해 전체 테스트를 실행했다.
- 상세 검토: 레시피·조합·댓글·팔로우·사용자·인증 스키마, 검색·트렌딩 정렬, 레시피·조합·댓글·팔로우 서비스, 이미지 수집·정리, 공개 이름과 주요 호출부, 레시피·조합 폼, 제출 잠금 훅, 게시글 좋아요 연결 코드.
- 기존 테스트 상세 표본: 게시글 스키마·멘션·HTML 정제, Storage 경로, 콘텐츠 권한. 나머지 기존 테스트는 파일 존재 확인이며 전체 품질 판정은 아직 하지 않았다.
- 프로젝트 전체의 모든 동작을 분류 완료한 보고서는 아니다. 전체 라우트·UI, 커스텀 에디터, 공유·인증 콜백 세부 흐름, 저장소별 전체 쿼리, 실제 DB 정책·함수 정의, 운영 도구는 후속 검토가 남았다.
- 기존 대규모 파일 이동·수정·삭제가 작업 트리에 있다. 이번 작업에서 이를 변경하지 않았다.

## 해결된 판단 보류 후보

### Q1. 레시피 생성·수정의 태그와 조리도구 상한

- 위치: `src/domain/recipe/schema.ts:54`, `src/domain/recipe/schema.ts:119`, `src/app/recipes/ui/RecipeForm.tsx:112`
- 생성 스키마는 태그·조리도구 최대 10개, 서버 수정 스키마는 최대 20개다. 수정 화면도 생성에서 파생된 `recipeFormSchema`를 사용해 10개 제한을 받는다. 기본 정보 화면의 태그 안내도 최대 10개다.
- 분류: A. 테스트 필요성은 확정, 기대 상한은 보류.
- 영향: 서버 수정 경로에서 11개 이상을 저장하면 다시 수정 화면을 사용할 때 검증에 걸릴 수 있다.
- 권장: 현재 화면 기준대로 레시피 생성·수정 모두 태그와 조리도구 각각 최대 10개로 통일.
- 사용자 결정: 생성·수정 모두 태그와 조리도구를 각각 최대 10개로 통일.
- 기존 검증: 관련 테스트 없음.

### Q2. 조합 구성 항목의 최소·최대 개수

- 위치: `src/domain/combo/schema.ts:19`, `src/domain/combo/schema.ts:43`, `src/app/combos/ui/form-sections/CombinationFields.tsx:104`
- 폼은 항목 추가 버튼을 10개에서 막지만 항목 전체 삭제는 가능하다. 폼·서버 배열 스키마에는 최소·최대 개수 제한이 없다. 다른 필드가 유효하다면 구성 항목 0개도 이 스키마에서 거부되지 않는다.
- 분류: A 규칙 / D UI 연결. 테스트 필요성은 확정, 최소 개수의 제품 의도는 보류.
- 영향: 구성 항목 없는 조합 또는 화면 제한보다 많은 조합을 서버가 허용할 수 있다.
- 결정 근거: 조합은 둘 이상의 레시피·상품을 묶는 기능이므로 단일 항목은 조합으로 보지 않는다.
- 사용자 결정: 최소 2개, 최대 10개로 통일.
- 기존 검증: 관련 테스트 없음.

## 2단계 진행 상태

Q1·Q2의 기대 결과를 반영하고 확정 A 대상의 단위 테스트를 작성·보강했다.

- 레시피 생성·수정의 태그와 조리도구를 각각 최대 10개로 통일했다.

- 게시글 스키마·멘션·HTML 정제·콘텐츠 권한 테스트의 경계값과 실패 원인 단언을 보강했다.

- 정책 수정 전 관련 테스트에서 11건 실패를 확인했고 수정 후 통과해 회귀 감시가 작동함을 확인했다.
- 전체 결과: 27개 테스트 파일, 221개 테스트 통과. ESLint·TypeScript·Next.js 프로덕션 빌드 통과.

현재 PC에는 로컬 PostgreSQL과 Docker Desktop이 없고, 저장소의 로컬 마이그레이션은 14개인 반면 연결된 DB 이력은 61개라 초기 스키마도 빠져 있다. 따라서 `supabase test db --local`의 실제 실행은 아직 완료하지 못했다. 연결된 원격 프로젝트에는 테스트 데이터를 생성하지 않고 읽기 전용 구조 점검만 수행했다.

실제 RLS·RPC·Trigger 동작과 Storage 삭제, 브라우저 상호작용은 DB 통합·E2E 대상이다. 이 보고서는 프로젝트 전체 E2E 완료를 의미하지 않는다.
